# LookDev 与 Diorama：模型差异、沉浸感与共享迁移

2026-09-08。本文依据现存 Blender 生成器、实际 GLB 和 Godot 加载代码做审计。**LookDev Live 已完成当前地面、北轴、14人口与五位漫步的共享同步，完整场景 QA 8/8 与原生物理报告均通过。** `run_lookdev.ps1` 已进入独立 Live 场景，`-Archive` 保留历史版；微缩入口仍为 `run_diorama.ps1`。最终画面重拍与视频验证单独记录，不把技术通过当作用户已批准美术效果。

**两版不是“真实尺寸校园”和“缩小校园”的区别。它们使用同一米制空间，但采用不同的造型概括、材质、摄影与展示方法。** 当前 Live 与 Diorama 都实际承载后续人口、漫步与北轴；旧 LookDev Archive 仍是独立早期环境成果，不能靠换相机自动获得后续内容。

## 真实尺寸：同一栋一教，不同的外饰完成度

`SCENE_SPEC.md` 与 `build_campus.py` 明确采用 **1 Blender helper unit = 1 Godot unit = 1米**。辅助函数把 Godot 的 `(东,上,南)` 转成 Blender `(东,-南,上)`，GLB 使用标准 Y-up 导出；两版根节点没有整体缩放。

一教主体都来自 `build_campus.py` 的 `hallparts`：北楼体块 **124×17×15.6 m**，两翼各 **14×17×42 m**，中部突出体块 **31×17×11 m**；四层窗列中心为 `2.5 + 4.05×层号`。Diorama 生成器先从旧 Architecture 中筛选复制一教范围的顶点，再追加外饰，没有把墙移动到一个更小的 U 形里。

本轮还只读解析了两个实际 GLB。二者没有非1节点 scale；按一教范围裁取的顶点包围盒如下，包含窗台、檐口、台阶等外饰，**不能当作新的测绘主体尺寸**：

| 实际文件 | 选区最小点 | 选区最大点 | 包围盒差异来源 |
|---|---|---|---|
| `architecture.glb` | (-62.50,0,164.30) | (62.50,17.58,222.40) | 旧 LookDev 立面与外饰 |
| `dioarchitecture.glb` | (-63.975,0,164.30) | (63.975,17.89,222.58) | 追加女儿墙、后窗、屋顶边缘与更宽倒角 |

制造类边缘的倒角宽度，旧版为 **1.8 cm**，Dio 变体为 **6.5 cm**，都用3段倒角。后者更容易在高位远景获得连续亮边；人高近景会更圆润。Diorama 还补了后立面窗框、连续屋顶轮廓、入口台阶/门厅、墙根和庭院小品，所以不能简单说它是“低面数缩水版”：当前一教裁取数据约有137.8万/100.6万个属性顶点（Dio/旧版，含导出重复顶点），面数本身不能代表真实感或视觉品质。

## 树木与表面：细叶透空与整体冠簇

| 项目 | 旧 LookDev | Diorama 0.7 |
|---|---|---|
| 树冠组织 | 弯曲树干、主枝、次枝、细枝与大量小叶；冠内可透空 | 主枝和次枝仍存在，大/中/小分瓣冠簇形成可读整体体积 |
| 叶片几何 | `leaf()` 每片13顶点、12三角形，带中脊弯曲的薄片；不是朝向相机的 billboard，也没有用照片透明叶卡贴满球体 | `crown()` 为16圈×32段的连续分瓣曲面，焊接并平滑法线；不是早期低分段石块树冠 |
| 物种与个体 | 3种生长结构×3个体，基准高度约8.2/12.8/10.2m，另有实例缩放 | 3种×3个体，基准高度约7.4/12.4/9.2m，春日樱花粉白冠簇更明确 |
| 材质 | 六组原创1024² Base Color / Normal / ORM；砖、石、草、铺装、木、树皮有更明确的细纹理 | 沿用贴图基础，但草地和砖红做大色块统一、降低法线/斑驳频率 |
| NPR光照 | `academic.gdshader` 将常规漫反射与柔和阶调混合，保留粗糙度、GGX高光、AO与叶背透光 | `diorama.gdshader` 增强阶调混合、色板归一和接触层次，仍接受真实场景光照 |
| 玻璃与角色 | 玻璃独立 PBR；基类虽支持 TikuFace/毛衣材质，旧场景没有真正加载后续人物 | 相同玻璃基础，专用脸部/服装材质；14人口和五位漫步实际接入 |

旧 LookDev 的最终叶子已替换最早的实心低分段冠壳。它也没有达到照片级植物仿真：分枝与叶簇仍可看出程序规律。Diorama 的实体冠簇则主动概括叶子，在总览中更安静，近看更像精心制作的模型。迁移应恢复旧版的叶片组织，而不是把 Diorama 树换成更高多边形球体。

## 为什么同样的米制模型，沉浸感会不同

旧 LookDev 主要采用人高透视，使用共同玩家的 **1.65 m眼高**；地面机位大致44–65° FOV，建筑遮挡、近大远小和视差提供人在校园中的尺度线索。界面设定为夏末16:10，偏灰绿植被、较明确纹理、空气透视和远处树墙帮助场景延伸。

Diorama 默认高位3/4正交或弱透视，总览可以看到完整底座轮廓。早期核心基座为160×120m、石质厚边和木底，新模块延续展示边；下方还有独立中性摄影背景平面。春日粉白冠簇、较宽圆润亮边、减弱雾与强化接触阴影共同形成“收藏模型”的阅读方式。**这主要是观察方式和视觉组织，而不是模型单位变小。** 同一角色从人高视角看仍是人尺度，换高位正交后才会像模型里的小人。

范围也不是比较美术等级的快捷指标：旧版使用较大的规则地面网格与简化背景楼，范围广不等于那里都精修。当前0.7使用有资料依据的北轴/双池模块与周边接段，可展示底座并集约55,933.5㎡，包含楼体和水体，仍非完整东区。需要比较同一条路、同一眼高和相近光照下的内容，不能拿旧人高图与新高位总览直接判断模型“变矮”。

## 当前代码关系与本轮迁移方案

历史入口 `scenes/main.tscn → campus.gd` 保留为 Archive。当前微缩入口 `scenes/diorama.tscn → diorama.gd`，后者继承前者的通用工具，覆写地景与生命层。旧 `campus_world.scn` 是烘焙环境集合，不是最新14人口/漫步运行场景。

本轮已采用 `lookdev_live.gd extends diorama.gd` 和独立 Live 场景入口：**共享已经验证的世界与玩法，按 LookDev 视觉模型补齐必要的接触形状。** `run_lookdev.ps1` 默认进入 `scenes/lookdev_live.tscn`，`run_lookdev.ps1 -Archive` 进入历史 `main.tscn`；`run_diorama.ps1` 保留微缩版。新入口的实际实例化与运行回归已有报告，不以规划文件名称代替启动证据。

可直接复用：

- `population.json`、`wave2_nodes.json` 的14个实例、身份 GLB、动画、脚/手接触与角色碰撞。
- `campus_wander.gd`、`wander_routes.json` 及固定箱子/落叶的故事 anchor，不再复制一份漫步逻辑。
- `north_axis_layout.json` 的真实双池 outer/holes、亭岛、四桥、建筑与路网；`scene_modules.story_nodes()` 统一解析 home。
- 当前陆地承托、水域禁入、真实人尺度玩家、低台阶处理、连续桥口和已修正的道具体积净空。
- 已有长椅、车架、自行车、公告栏、路灯和草簇；是否替换外观与是否存在碰撞分开控制。

视觉覆写：

- 选用 LookDev 一教外观或独立导出的兼容变体；保留真实主体比例、已完成后院和入口可用性。
- 使用细叶树种与低灌木，在当前路网/角色通道内重新检查冠幅和树干位置。
- 使用 LookDev 表面频率、草地色差、暖光/冷填充、雾与人高透视；角色脸部/服装仍保留独立材质，不把全部人物一起强行改色。
- 隐藏展示底座与中性背景的可见部分，保持上方陆地碰撞。外围景观收口与可达范围各自明确，不能因隐藏基座让玩家看见或走进空洞。

这属于**中等集成工作，主要难点是实机视觉和接触验证**。角色、地图、路线和大部分中尺度资产不必重做；但也不是换一行 Shader 就完成。应让两个入口共用后续布局改动，减少再次发生“微缩版有新人、沉浸版仍是空场”的维护分叉。

## 迁移风险与验收门

1. **旧整包资产会重复北轴。** `architecture.glb` 不只是一教，还含旧门、旧亭；`sitedetail.glb` 含旧桥与部分背景修饰。直接叠到新北轴会出现双亭、重叠台阶或闪面。必须按区域/对象筛出一教，或独立导出新文件；不覆写旧 GLB。
2. **不能恢复旧水陆事实。** 旧 `site.json` 曾漏读东池 relation，旧规则地形和旧桥碰撞也不代表0.7修复结果。保留新 `north_axis_layout.json` 的岛孔、桥许可和真实连续路径，外观迁移不倒退空间精度。
3. **可见草地不是碰撞。** 隐藏底座后仍需完整可行走地面；不得把水面或建筑内部补成草地。保持17条真实连续路、9项禁入和现有陆地/水域采样作为回归范围，新增视觉后重检受影响处。
4. **树的大小和成本都可能改变。** 细叶网格包含更多细碎轮廓、双面片和阴影；旧版341棵树的布置不能整批复制到新故事节点上。先守住路宽、桥口、角色面部和亭门净空，再检查普通窗口帧耗时，不拿4K出图速度当游玩性能。
5. **同一角色在新光照下仍应像自己。** 除数值闭环和脚锁定，还要在新场景检查做题家的窄脸/镜框、手里道具、衣领、皮肤与头发受光。共享材质函数能处理某个材质名，并不证明角色已经被正确加载。
6. **道具检查完整体积。** 北轴桥口指示牌已从 `(73,79)` 移到 `(73,82.2)`；迁移不能恢复旧牌位，也不能只检查支柱原点。牌面、桥栏、箱盖与玩家胶囊均要保留净空。
7. **基准回归与新版本通过分开。** 两版旧资源哈希保持，只说明没有误覆盖；Live 还必须实际启动、出现14个节点、五位真迈步、草地可走、北轴连续，产出同机位对照与新图。新图的代理自评不能自动变成用户接受记录。

## Live 实现记录与同机位对照

当前独立入口：[lookdev_live.tscn](../godot/scenes/lookdev_live.tscn) 使用 [lookdev_live.gd](../godot/scripts/lookdev_live.gd)，后者直接继承 `diorama.gd`。原人口、五位漫步、北轴模块和陆地碰撞由继承链实际建立；不再把材质兼容误写为已经加载角色。[完整 QA](../renders/lookdev_live/validation.json) 的8项全部通过，[原生物理记录](../renders/lookdev_live/runtime_qa.json) 同为 `passed=true`，包含17条连续路线、9项禁入与新模型接触；方法见 [LOOKDEV_LIVE_QA.md](LOOKDEV_LIVE_QA.md)。

实际覆写范围已收敛如下：

- **建筑：**只加载独立 `lookdev_teaching_hall.glb`、现有 `north_axis_architecture.glb` 和 `north_axis_surroundings.glb`。一教从旧 LookDev 整包按原世界坐标筛出，入口采用连续修正台阶；旧门、旧亭没有再次整包叠入。根变换保持单位缩放。筛选边界、台阶与碰撞建议见 [一教导出清单](../godot/assets/lookdev_teaching_hall_manifest.json)。
- **小品与背景：**复用 `diositedetail.glb`，背景换为独立 `lookdev_context.glb`。原核心座椅、自行车设施等故事接地关系继续保留；外侧远景不代表额外可游玩校园。
- **树木：**把 `diotree` 的物种和个体索引映射到 `tree0/1/2` 与 `b/c` 细叶变体；当前树位仍来自共用布局。最终碰撞使用9个变体各自缓存的实际 `Bark/Trunk` 三角形，裁取资产坐标 `y≤2.4m`，保留原实例完整变换。根部外扩不会再被拉成整根圆柱；测量半径仅留作记录，不作为最终碰撞形状。103棵可达区树的412个四向截面与可见网格对比全部通过，最大差约 **0.0000458m**。一教入口12个可见/物理承托对照点误差均为0；这是有限采样证据，不宣称每个表面都做了穷举。
- **表面与照明：**环境改用 `academic.gdshader`；脸部与服装保持专用 Shader。`lookdev_live_visuals.gd` 提供暖太阳、偏冷天空填充、ACES、SSAO/SSIL、反射与低密度雾。它是更细腻的半写实 NPR，不宣称照片写实。
- **展示边界：**隐藏厚底座和摄影背景，在原外围物理边界上建立可见栏杆；较远的视觉地面与树幕只衔接画面，既不把水域变陆地，也不解锁围栏外游玩范围。

[离线对比画廊](../renders/lookdev_live/review.html) 将人高/近景的 `01_hall`、`04_bridge`、`07_tiku` 放在最前；同名 Diorama 图片在 `renders/lookdev_live/diorama_ab/`。两组由同一个 [捕获脚本](../godot/scripts/lookdev_live_proof.gd) 使用相同机位与动作时间输出，季节、太阳和材质是有意保留的视觉差异。世界总览列为附图，旧 `hero_04` 单独留档，不把它混入本轮公平 A/B。

重新生成画廊：在项目根目录运行 `python tools/lookdev_live_review.py`。工具只读原始 PNG，按两份捕获报告逐项核对 **camera、fov、projection、size、time、resolution**，再从 PNG 文件头检查实际3840×2160像素；输出 `comparison_validation.json` 和 `review.html`。没有图或报告缺项时不会计为完成。参数相等只证明比较条件一致，不代替美术质量、角色身份、连续步行和碰撞验收；视频文件存在也不自动代表解码通过。

保护验证分为两层：原 `accepted_v0_4` 与 `accepted_v0_5` 合并的 **59项历史冻结文件**由场景 QA 核验；本轮迁移前 `baseline.json` 覆盖更广的 **88项文件与21张历史截图**，已逐项重新计算 SHA-256，全部保持，见 [preservation_validation.json](../renders/lookdev_live/preservation_validation.json)。二者有重叠，不能相加当作独立资产数量，也不能把迁移留档自动写为用户接受记录。本轮视频尚未在本文记为验证通过。
