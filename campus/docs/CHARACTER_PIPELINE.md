# 角色生产流程

目标：复用已验证的方法，减少重复研究与无效渲染。**角色成功以 Godot 实机近景保留身份为准，设定图只是中间成果。** 做题家当前版本已经用户接受；后续普通 Ambient 不复制其脸，也不重复打开这一 Hero 的设计阶段。

## 阶段与质量门

| 阶段 | 最小产物 | 通过条件 / 失败时返回 |
|---|---|---|
| Reference Research | 1 张身份主参考 + 约 6–12 张高相关辅助图；来源、用途、许可 | 真正查看图片，区分脸、衣着、姿态和环境依据；不把搜索关键词当设计 |
| Character Bible | 一页身份锚点、比例、色板、衣服、道具、行为、禁止项 | 用具体脸型/轮廓/神态描述，不能只有“眼镜 + 蓝衣服”标签 |
| Static Identity Approval | 正面、3/4、侧面、背面、关键姿态和表情的设计证据 | 主参考识别特征成立；已有用户接受的设计直接沿用，不重复求确认 |
| 3D Modeling | 可复建 Blender 源、明确单位/轴向、GLB | Macro 比例 → Meso 头脸与衣领 → 必要细节；三视图轮廓均成立 |
| Texture / NPR | 绘制细节、材质、UV 与独立关键几何 | 脸的眼睑/唇/胡茬可绘制；下颌、鼻唇、眼镜、发型需要体积；真实受光 |
| Godot Close-up Validation | 同设定视角的实机正面/3/4/侧面、场景实际近景 | 在场景光、树影和最终 Shader 下仍像；失败回模型/纹理，不抢先做动画变体 |
| Animation | 克制闭环、接触约束、阶段样本 | 手—笔—纸、脚—地、身体—座椅/自行车接触正确；眼先动、头后跟、留停顿 |
| Scene Integration | 分区位置/路径、碰撞、读得清的小故事 | 不挡主路、不过密、缩远仍有剪影；不为特写牺牲实际游览 |
| Final QA | 真实截图、一个完整循环、验证报告、局限 | 数值与艺术两类检查都通过，注册表更新；不能只写“模型已生成” |

Ambient 已有项目风格与功能主参考时，Bible 可以合并为一个简短角色说明，设计证据可直接用生产模型静态多视图；无需每人重新生成大幅设定图。独立 Hero 身份仍须完整近景质量门。Creature 重点验证种类轮廓、接地、体量和微动作。

## 做题家实际教训

- 失败根因是模型身份损失：蛋形头、弱下颌、粗横条眼、黑半球头发、近八边形厚镜架和硬片衣领。Shader 无法补救这些结构。
- 修复方式是冻结已接受的设计，建立连续头骨与鼻唇体积，用绘制眼睑/眉/嘴/胡茬与薄矩形镜架共同保留身份。站姿像还不够，坐姿低头、扶镜和侧目都要近看。
- 衣着变体复用 `blender/scripts/tiku_head.py` 与同一面部纹理。两套导出 GLB 的头部位置、法线、UV 哈希完全一致是回归证据；哈希只能说明同源，不能代替“像不像”的审查。
- 笔尖、本子与手部目标约束先成立再增加动作。路边长椅前无桌，本子由腿承托；随意添加桌子会破坏真实叙事。
- 初轮路边角色踩树根、夹书仍像竖起的摊开本子。实际换到铺装路缘并改闭合教材，而非通过摄影角度藏穿插。
- 目前 Hero 每体约 23.5–29.3 万三角面、14 材质，有肩肘分件与衣服刚性限制；它是少量 Hero 基准，不能照此成本复制人群。后续优化先保持身份，按真实测量建立 LOD。

## 复用与构建合同

| 内容 | 当前执行来源 | 修改边界 |
|---|---|---|
| Hero 头脸 | `blender/scripts/tiku_head.py`、`godot/assets/textures/tiku_face_albedo.png` | 用户接受，默认冻结 |
| Hero 生产模型 | `build_tiku.py`、`tiku_boy1*.blend` / `tiku_boy1*.glb` | 只有明确 Hero 任务才重建 |
| Hero 动作 | `godot/scripts/tiku_actor.gd` | 保持命名关节、IK、32 秒循环与 API；复用不等于所有人同动作 |
| 四套当前 Ambient | `blender/scripts/build_population.py`、`godot/scripts/ambient_actor.gd` | 共用成人化造型方法，独立衣发剪影和行为；不重建 Hero |
| 既有动物 / 历史 Q 版 | `blender/scripts/build_life.py`、`godot/scripts/scene_life.gd` | 猫鸟复用；旧 Q 版学生留档，不回填当前人口 |
| 人口部署与动作路径 | `godot/data/population.json` | 唯一部署来源；注册表是可读快照 |
| 模块和边界 | `godot/data/module_layout.json` | 唯一实例来源；地图仍以 `site.json` 为依据 |
| 摄影与验证 | `diorama.gd`、`tiku_proof.gd` 与输出元数据 | 截图表引用运行结果，不维护第二套参数事实 |

新增参数化资产只应有一个规格来源（尺寸、色板、变体、周期、路径、随机种子），生成器、运行时和 QA 读取它或导出自它。禁止让同一人数、坐标或周期散落成互不一致的“真实值”。历史硬编码只在变更范围内集中，不为小任务全面重构。

构建前保存被改资产哈希和上一版证据；先在新 ID / 输出目录构建验证，再更新场景引用。同身份可复用头部、服装基础和绑定；新身份至少改变脸/发轮廓、体型或衣服剪影，不仅换颜色。选择足够支持微叙事的最低绑定复杂度。

## 证据与节省规则

材料分为 `references/`（参考）、`blender/source/`（生产源）、`godot/assets/`（运行资产）、`renders/<round>/`（实际截图/视频/报告）。图片标明 Concept / Blender / Godot，不能用生成图代替运行截图，也不能修图掩盖建模问题。

先用固定脸部正面、3/4、侧面定位身份问题；通过后再做动作和校园全景。解析失败先查日志，不继续批量渲染。完整循环通过后，只有动作/约束变化才重拍整段；仅移动站位时复拍受影响近景、接地和总览。

现有 Hero 命令：`build_tiku_assets.ps1 -Proof`、`capture_tiku.ps1`、`tools/verify_tiku_identity.py`。只有明确 Hero 变更才用它们重建。当前 Ambient 用 `build_population.ps1`，`capture_population.ps1 -Verify` 验证、无参数捕获12张静帧、`-Motion` 输出动作帧并编码；`python tools/population_review.py` 只更新展示页。最终查 [QA_CHECKLIST.md](QA_CHECKLIST.md)，记录真实差距，不将可接受人物宣称为动画电影最终成片。

本轮新增经验：先在原机位比较新旧所有 Ambient，不能只检查新资产。首轮发现旧拍照者/背资料者圆头积木感与新增角色不统一，最终用同一生成器输出4套不同衣发的模型。又发现后院地垫顶面 y=.07，而读者鞋底埋到地面；现在鞋底 world y=.075、地垫实体承托一致，保留5毫米间隙，最终人物脚面完整可读。局部坐标“脚在0”不能替代实际世界地表高度检查。
