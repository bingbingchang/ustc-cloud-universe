# 校园性能优化规范

**2026-10-12当前更新：路网、成熟树种与北区楼群。** 当前覆盖112,199.823㎡／20.142%，本轮净增40,987.087㎡；已建范围实际渲染28条道路段，新增树种部署层156棵、5件GLB，以及教五、教学行政楼、管理科研楼、MBA中心与新北门。11条人物实走及7组检查通过，含楼体／法桐网格碰撞、北区跳跃和新增教五楼前通道；4个场景入口各33,699接缝样点零缺口，旧59项冻结文件未改。下方广场及人物模式旧帧率是扩建前的历史记录。

人物前方的明暗横带来自级联阴影中的大建筑投影裁切。只混合级联会柔化横带，但无法恢复被裁掉的投影；正交模式和增大pancake的诊断都恢复了完整轮廓。游戏最终保留四级阴影，在 `campus_game.gd.apply_quality()` 中将 `directional_shadow_pancake_size` 设为120，并开启 `directional_shadow_blend_splits`；两档阴影距离仍为100／180米。120是当前一教与约64米北区楼体的实测选择，参数含义见 [Godot DirectionalLight3D](https://docs.godotengine.org/en/stable/classes/class_directionallight3d.html)。

阴影回归使用真实SpringArm镜头，在庭院z196／202／208／214移动，覆盖默认第三人称、两个更低俯角和第一人称，流畅／精细两档各测旧20设置与最终默认。验证实例冻结日照、NPC和场景过程，以固定世界地面24厘米区域的投影取样比较光度，并排除遮挡与人物移动阴影；保存64张1600×900原生图。8组最终世界阴影稳定性检查通过，最终P95漂移0.040–0.052；旧流畅档默认镜头P95为0.126，明显变化区域比例11.4%→0.79%。[实际回归](../renders/shadow_band/validation.json)，复现脚本 `tools/validate_shadow_band.gd`。这些是阴影正确性结果，未用来推算帧率收益。

本轮原生移动短测在1600×900、流畅档、4×MSAA／TAA下进行，人物实际持续前走，四处窗口焦点均100%。数据及新实机图记录于 [visual_validation.json](../renders/campus_network/visual_validation.json)。这是新增道路、楼群和树种之后的短测，未与此前静止镜头或不同画质成绩计算优化收益。

2026-10-12新增可玩入口 `OPEN_GAME.cmd`，以下历史14人口条件用于复现旧报告。当前游戏性能采样使用16个NPC／动物加1位玩家，角色和环境动画保持运行。镜头必须包含第三人称移动、转镜头、跳跃和窄路收近；扩区后再增加连续穿区采样。

当前游戏已有两档：精细档768×432倒影、移动逐帧、180米阴影；流畅档512×288倒影、最多30Hz、100米阴影，细小植被空间批次在90米外剔除（8米迟滞边界）。两档均保留现有树冠网格LOD、24米批次、MSAA/TAA和SSAO/SSIL，可按F3对比。具体本轮结果见下方。

目标是完整东区可持续扩建，同时保留已认可的构图、光色、人物与近景精细度。性能必须与美术、地图和通行一起验收。

## 测量先于改动

运行 `profile_campus_performance.ps1` 顺序复测基线、优化、移动与扩区；加 `-Diagnostics` 可复测单项关闭诊断。运行时保持窗口聚焦，不同时运行其他图形测试。输出在 `renders/performance_upgrade/`；`python tools/performance_review.py` 用完成的报告与原图生成对照页。

固定1600×900、4×MSAA、TAA、关闭VSync、14个生命元素与相同机位。每机位90帧预热、180帧采样，记录实际帧间隔的均值、P95、绘制调用、提交图元、窗口焦点、角色数量和画质。只有同轮、同内容对照用于计算收益。单独关闭效果是诊断，不是最终交付；关闭后的整帧变化不能当作该模块独立GPU耗时，各项差值也不能相加。

短采样之外必须检查移动视角。静止相机允许复用倒影，不能用静止高帧率宣称游玩时同样快。完整东区阶段还应增加至少数分钟的穿区测试，记录加载卡顿、内存和温度；本轮短采样不替代它。

当前建议目标：本机普通人高视角60 FPS、P95不高于20ms；全景单独记录。新增区使同机位帧时间增加超过10%时，先分析再继续堆叠。目标用于约束后续工作，不是对所有机器的性能承诺。

## 网格、植物与批次

- 新高密度资产必须生成LOD。导入时生成了LOD，不代表运行时重建的ArrayMesh仍携带LOD；禁止只拷贝最高级索引却假设已优化。
- 当前离线命令为 `build_render_lods.ps1`。LOD缓存包含源GLB SHA，源文件变化后重新生成；运行时遇到过期缓存自动回退原网格并提示。LOD最高精度顶点和索引必须与原模型一致。
- 重复物件按空间分组。当前采用24米网格内的MultiMesh批次，并复用同源网格和材质。不要把整条大道或整个校园的高密度植物塞进一个批次。
- LOD变化不改变位置、碰撞与行为；近景优先保留轮廓、树干接触和遮挡关系。用同机位实机检查叶片是否过早消失、色块是否破碎。
- 分批后的替换、隐藏逻辑必须依赖稳定资产标识，不能依赖可能被引擎重命名的节点名称。可见资产实例数应与优化前一致。

依据：[Godot的MultiMesh优化说明](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)指出单批次不能独立剔除其中每个实例；[Mesh LOD说明](https://docs.godotengine.org/en/stable/tutorials/3d/mesh_lod.html)说明同一MultiMesh共用LOD判定，分开相距较远的实例有助于剔除与细节选择。

## 倒影、光照与画质

优先减少重复工作，避免先删掉决定风格的光色。当前保留原分辨率、4×MSAA、TAA、SSAO与SSIL，树木和角色仍然存在。测试表明本场景单独关闭SSIL收益很小，因此未作为主要优化。

平面倒影仍使用768×432渲染；相机移动时逐帧更新，静止时最多12次/秒，水波着色继续逐帧运行。倒影纹理与投影矩阵作为同一份快照更新，避免只更新矩阵导致图像错位。后续改变FOV、投影类型、画幅或相机切换时都要验证刷新。

大范围灯光、阴影、反射和透明层叠都应单独测量。不要以透明卡片替代几何后就默认更快；不能为遮挡剔除随意增加破坏校园辨识度的墙。

依据：[Godot 3D优化](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)讨论剔除、透明物体、光照和大世界分块；[遮挡剔除说明](https://docs.godotengine.org/en/stable/tutorials/3d/occlusion_culling.html)指出开放场景可能缺乏足够遮挡机会，额外CPU开销需测量。建筑街区可后续实施遮挡体，本轮湖园没有盲目启用它。

## 完整东区的分区与加载

艺术区域与渲染批次分开：一个“樱花大道”艺术区可覆盖多个24米渲染批次。未来需要区域清单，记录GIS范围、参考图、资产、碰撞、人物、加载邻接、内存和性能证据。

完整东区不沿用“全部内容永远最高精度常驻”的方式。规划近区完整呈现、中区LOD、远区简化建筑轮廓，随后加入异步预加载与区域卸载。保留相邻区域的地面和导航连接，人物跨区活动与故事状态不能因卸载丢失。这是后续架构任务，本轮完成的是空间分批与网格LOD，尚未实现全校流式加载。

远景HLOD与简化材质可进一步使用，但需检查切换、透明过渡及阴影成本。[官方HLOD说明](https://docs.godotengine.org/en/stable/tutorials/3d/visibility_ranges.html)列出了距离切换和过渡的取舍。

树池与树木部署还需遵守 [树池定位合同](TREE_BASINS_AND_NORTHWEST.md)：共用位置、按实际根部尺寸定内径，并验证植被净空。

|---|---|---|
| 樱花大道 | 77.5 / 13.8 | 94.7 / 12.2 |
| 一鉴亭桥头 | 77.6 / 14.2 | 101.4 / 11.5 |

原始记录为 `renders/gameplay/validation.json`，复现运行 `run_gameplay_checks.ps1`。这是同轮两档游戏画质的短测；主要收益来自降低倒影第二次场景绘制的频率与分辨率，以及远处细节提交，具体各项成本仍需分离测量。数分钟穿区卡顿与未来完整东区的内存／加载性能留待覆盖扩建时测量。退出仍有此前既存的7个Texture RID释放警告。

## 每次扩建的交付条件

1. 保存同轮性能基线及原生截图；明确该次是优化对照还是增加内容对照。
2. 为新资产生成并验证LOD；避免额外材质实例和跨区巨型批次。
3. 验证静止、移动、人高、近景和总览；先看画面关系，再看细节损失。
4. 跑 `check_ground_seams.ps1`，再跑原生路线、禁入、人物与网格接触检查。
5. 记录最高精度网格、已有GLB/贴图/布局的保护结果；通过不能只意味着“画面能打开”。
6. 报告新增内容后的实际帧率，不拿扩建前成绩冒充扩建后成绩。

构建API使用官方 [ImporterMesh](https://docs.godotengine.org/en/stable/classes/class_importermesh.html)，LOD在离线构建中生成，运行时读取缓存，不在每帧或每次进入区域时重新简化网格。
