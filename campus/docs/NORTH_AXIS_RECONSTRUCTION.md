## 本轮解决的空间错误

东池的完整数据是 **relation 11542038**：外环 **way 290098996**，亭岛内环 **way 840391562**。旧数据用十点近似池形和一条斜桥代替，不能保留这种简化继续扩建。

新版 JSON 的 `ponds` 每项保存 `outer` 与 `holes`。西池采用原 OSM **way 290098995**；东池严格恢复原始外岸与内岛。西池范围约 X -61.697～-16.232 / Z 71.609～132.966；东池约 X 13.799～64.090 / Z 58.224～128.323。亭岛范围 X 36.680～54.171 / Z 72.153～87.022。两个池南端穿过旧核心北界 Z118，因而不能在新旧区各生成一套互相冲突的水岸。

一鉴亭中心保持 **(42.501, 80.789)**。亭平台使用 way306372994 的真实六边轮廓。北入亭桥由 ways306372996 / 840891953 组成，东入亭桥由 ways306372998 / 840891954 组成。西池曲桥使用 way290098999，保留 way290098998 的短支。没有新增虚构的跨湖捷径。

OSM 的东池西岸步道 way306373007 与同一快照中的外岸线部分交叉，来源之间有绘制时间或精度冲突。此处优先保留完整岸线，把游园步道中心向陆侧退到约 X11～17，保留从玉泉路到北桥头、再返回南侧路口的关系。此调整是**可通行性约束下的推断**，不是实测原路逐点复刻。

## 连续地面和水体规则

地面 Y0，铺装 Y0.08，水面 Y-0.05，桥与亭平台 Y0.34。水位沿用旧核心，避免被旧底座 Y-0.1 的顶面盖住。桥宽主支 2.6m，西短支 2.0m；这些横断面数值是基于照片和实时游览的合理估计，不是测绘尺寸。

新陆地先分 8m 格片，逐片扣除池外环；若 Godot 差集返回反向的洞环则递归再细分。最终所有片合并成一张草地网格，再独立生成凸体承托。不能直接把 `clip_polygons` 的每个返回环当实心面。亭岛独立恢复地面。

完整双池的可见水面、岛和岸石由北模块统一生成，包括 Z118 以南的旧区池尖；旧核心只按新外岸裁草地，停止旧水面、岸石和水域碰撞。水域禁入碰撞先扣除桥面通道和内岛，桥面有独立凸体，入口有 2.2m 长连续缓坡。桥栏、亭柱、北门柱等与可见模型对应的实体碰撞，由建筑资产 manifest 交主集成生成。北模块不创建横跨门洞的整块“建筑墙”。

## 种植、小品和微型故事

继续使用现有 diotree、dioshrub、grass、bench、lamp，树列、湖岸树与院落树分层组织。60 个候选树点按建筑、水、步道净空过滤；小灌木集中在树下和岸侧，草簇少量分布。桥/水禁入规则优先于装饰密度。

长椅置于独立铺装小垫，前面不加桌子。标牌分别解释玉泉北路、一鉴亭和眼镜湖；全部补柱与牌面碰撞。新加入的设施不是对每一件现实小品精确位置的声称。

为主集成保留两个已有人物的新 home，不在本模块实例化人物：豆包 (1.6,0.08,39)，玉泉路上 Z29～48 缓步；三月七 (89.1,0.08,88)，天使路上 Z70～88 缓步。路线位于足宽铺装内，树、椅与故事路线分离；最终人口密度、角色事件与摄影视角由主集成统一核对。

## API 与验证记录

`north_axis_environment.gd` 提供 `layout()`、`build(c)`、`contains(Vector2)`、`boundary_openings(side)`、`walk_routes()` 与 `camera_spots()`。`contains` 表示新区域普通陆地，排除建筑和湖水；桥不是陆地，须结合 `bridges` 或实际物理查询判定可走。`build` 接收既有 campus 实例，使用其 `world` / `mats` / 资产实例化 API；不创建玩家和相机。

2026-09-08 独立 headless 检查（实际运行）：

- Godot 4.7.1 `--check-only` 通过，无语法错误。
- 无 GLB 加载的环境夹具构建 84ms；498 个陆地片合并一张网格，217 个道路片合并一张网格。该时间不代表完整场景帧性能。
- 5,739 个新陆地区域射线点均有承托；1,186 个湖内点均有水禁入体或桥面。
- 对新陆地可见网格逐三角形重心检查，落在水域的草地三角形为 0。
- 新模块内 8 条桥、岸路、住宅通道按 0.25m 采样，无缺失地面、水墙或建筑阻断。4 条进入旧核心的路线需要主集成测试，不计入上述独立通过数。

这套检查证明局部几何与可见地面没有明显孔洞，并不替代原生 Godot 玩家实走、桥栏交汇处测试和最终画面审查。资产/人物/截图验收由主任务继续完成。

整合后补充验证：运行 `capture_north_axis.ps1 -Verify`，实际原生场景验证报告为 `renders/north_axis/runtime_qa.json`，主流程汇总为 `renders/north_axis/validation.json`。第二轮完整运行退出码 0，所有项目通过：

- 17 条实际 CharacterBody3D 步行路线，29,832 个物理步；速度 1.8m/s，物理频率 240、时间倍率 4，使积分步长保持 1/60 秒。包括老门到核心、四支曲桥、绕亭柱穿亭、新旧东侧接缝、一教入口前场和两条旧核心草地回归。
- 5,739 个陆地射线点与 1,186 个水域点通过；20 个仅位于外围墙内的不可达边缘点明确排除，接口不排除。
- 9 次实际向禁入区域行走：两池、四栋楼、三条展示外边界，均被正常阻止。
- 五个漫步者临时固定在 home，并仅在地形实走期间关闭自身身体碰撞，结束后恢复。人物路线障碍另由主流程的 `walk_routes_obstacle_free` 校验，不把人物穿透当成正常游戏行为。
- 首轮定位并修正了自动路点跟随器：持续更新朝向，避免经过坡道后错过小路点；老门路线增加实测转折点；西曲桥短支的终点退后 0.65m，符合人形胶囊不能站到有限桥面的最外边这一实际约束。没有以扩大可走水面解决失败。

完整复测墙钟 145.622 秒。主汇总中的原资产校验、人口数量、密度、五角色漫步、路线无障碍与实机物理均为通过。

## 末轮桥岸路指示牌修正

荷叶与岛石加入后的完整复测中，穿亭路线在桥外岸 (74.1017, 78.6500) 再次停止。先保留 `renders/north_axis/runtime_qa_failed_before_followup.json`，随后增加尾迹再跑整场，在相同位置复现并保存 `runtime_qa_failed_with_trace.json`。

尾迹第 2106 个物理步记录到此前末帧报告漏掉的垂直接触：位置 **(73.7313, 1.5509, 78.9300)**、法线 **(0,0,-1)**。该平面正好是一鉴亭指示牌的正面：牌中心 (73,1.54,79)，宽 2.2m，厚 0.14m。牌面侵入了桥头 2.5m 步道；角色沿牌面滑到右下角后，连续地面接触耗尽了后续碰撞解算，因而最后只报告地板。过程中水平速度仍非零，不能把此例归因于失焦或停止注入前进输入。

已将整块指示牌的可见物与实体碰撞一起移到草地 **(73,82.2)**。原曲桥、桥岸路、穿亭路点与人物碰撞尺寸保持不变；没有通过关闭牌碰撞、扩大可走水面或移走路点回避失败。几何解释与前后位置另存 `bridge_exit_fix.json`。

自动实走器也补充了诊断完整性：保留途中出现过的水平障碍法线，记录输入强度与窗口焦点；逐路检查每个原路点都到达 0.14m 内，逐物理步水平位移小于 0.15m、空间位移小于 0.50m（允许原玩家 0.30m 低台阶处理），并明确禁止路中重定位。路线起点的测试摆位在计量前完成。最终通过状态以新版 `runtime_qa.json` 与主流程 `validation.json` 为准，失败证据不覆盖。

移牌后的最终整场实走实际完成：17 条原路线全部通过且连续，29,824 个物理步，9 次阻挡测试通过；墙钟 145.595 秒。实测最大单步水平位移 0.060003m、最大空间位移 0.305942m，后者属于既有低台阶动作。主流程所有汇总项通过。另由独立审查者计算三块牌面对所有路段的净空，进一步扣除玩家半径 0.28m、路缘 0.13m 和碰撞厚度修正后，新一鉴亭牌仍至少保留约 1.11m 余量，其余两块牌更宽裕。
