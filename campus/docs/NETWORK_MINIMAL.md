# 最小联机版本（Minimal Multiplayer）

版本：V0.1 · 2026-10-12
目标：证明「两个真人可以同时出现在同一个校园场景里、能看见彼此在跑、能互相说话」——
不是做完整网游，而是把「多人实时互动」从 PPT 承诺变成可演示的事实。

---

## 一、怎么用

**两台机器（推荐，也是正式演示的方式）**

```
A 机（当主机）：双击 campus\OPEN_NET_HOST.cmd
B 机（加进来）：双击 campus\OPEN_NET_JOIN.cmd，输入 A 机的局域网 IP
```

**一台机器（只做功能自测）**

⚠️ 同一台机器**不能同时开两个图形窗口**——见第二节。同机自测请用：

```
步骤 1：双击 campus\OPEN_NET_SERVER.cmd   （无窗口主机，不占显卡）
步骤 2：双击 campus\OPEN_NET_JOIN.cmd     （唯一的图形窗口，直接回车连本机）
```

命令行等价写法（走 run_game.ps1）：

```powershell
.\run_game.ps1 -NetHost                # 图形主机，默认端口 45888
.\run_game.ps1 -Server                 # 无窗口主机（同机自测用这个）
.\run_game.ps1 -NetJoin 192.168.1.5    # 客户端
.\run_game.ps1 -NetHost -NetPort 46000 # 换端口
```

游戏内：**回车**打开聊天输入框，再按**回车**发送。

**单机行为完全不变**：不传 `--net-*` 参数时，联机代码一行都不会执行。

> **不要用中文当 `-NetName`**。cmd.exe 是通过 ANSI 代码页把参数交给原生程序的，
> 中文名字到 Godot 里会变成乱码（`同学` → `鍚屽`）。留空即用内置的 UTF-8 默认值。
> 脚本已改为纯 ASCII，默认不再传名字。

## 二、为什么同机开两个窗口会失败（重要）

**症状**：先启动主机（图形窗口），再启动客户端，主机开始刷
`VK_ERROR_SURFACE_LOST_KHR`，或者客户端连日志都来不及写就崩掉（Illegal instruction）。

**看起来像显卡/驱动问题，实际是内存不够。** 实测数据：

| 项目 | 实测值 |
|---|---|
| 单个图形实例 工作集 | **2 746 MB** |
| 单个图形实例 私有内存 | **4 430 MB** |
| 本机内存 | **15.1 GB 总量** |
| 启动前的可用内存 | **约 1.3 – 4.1 GB** |
| 系统提交上限 / 已提交 | **40 GB / 37.4 GB** |

第二个实例要再拿 4.4 GB 提交额度，而提交上限只剩 2.6 GB —— **分配失败，进程在渲染器初始化阶段就死了**。
Vulkan 的 surface 错误只是这个失败的副产品，不是根因。

**验证结论（同一台机器实测）**：

| 组合 | 结果 |
|---|---|
| 图形主机 + 图形客户端 | ❌ 第二个实例启动即失败 |
| **无窗口主机 + 图形客户端** | ✅ **0 个 Vulkan 错误，连接与状态复制正常** |
| 无窗口主机 + 图形客户端 ×2 | ❌ 第二个图形实例仍失败 |

**所以：同机最多只能开一个图形窗口。**

**要同机开两个窗口，必须先腾内存**：关掉浏览器、ChatGPT 之类的常驻程序，
让可用内存回到 6 GB 以上，再：

```
campus\OPEN_NET_HOST.cmd      ← 第一个窗口
campus\OPEN_NET_JOIN.cmd      ← 第二个窗口（回车连本机）
```

`run_game.ps1` 现在会在启动图形联机实例前自动打印内存自检，
可用内存低于 6 GB 时会直接给出警告，不用再靠猜。

## 四、设计要点（为什么这么写）

1. **复用而不是重做角色。** `player_avatar.gd` 已经暴露了 `animate(speed, vertical, grounded, dt)` 这个接口，
   而它吃的正好就是网络要同步的那几个量。所以远端玩家不需要新的动画系统，
   直接把收到的速度/朝向喂进去，走路姿势和本地玩家天然一致。
2. **场景是纯代码构建的。** `campus_game.tscn` 只有一个根节点，世界、玩家、HUD 全在 `_ready()` 里程序化生成，
   所以用不了编辑器里的 `MultiplayerSpawner`，改成手动按 peer id 生成远端代理。
3. **注意挂载位置。** `player_avatar.gd` 的 `_ready()` 里会调用 `get_parent().get_parent().style(model)`，
   因此远端代理节点必须直接挂在校园根节点下（与本地玩家同级），否则拿不到材质重写函数。
4. **星形拓扑。** ENet 主机是 1 号 peer，客户端之间不能直连，
   所以客户端的状态与聊天先发给主机，由主机转发给其余客户端。
5. **静态体不复制。** 只同步玩家位置与朝向；校园地形/建筑由每个客户端各自用同一个随机种子（1958）生成，
   天然一致，不需要走网络。

## 五、顺手修掉的一个既有 bug

`godot/data/module_layout.json` 里有 **5 个模块没有 `name` 字段**（其中 4 个 `enabled: true` 且带 `polygon`，
包括郭沫若广场 `guo_plaza_03`）。`scene_locator.gd:44` 原本直接取 `s.name`，
一旦查询点落进这些多边形就会**每帧刷一条 SCRIPT ERROR**。

改成：

```gdscript
return s.get("name", s.get("id","未命名区域"))
```

这是既有问题，与联机无关——只是自检时角色会走到广场，才把它踩出来。
**注意：单机默认出生点在老北门一带，查询会提前 return，所以平时看不到这个报错。**

## 七、自检开关

加 `--net-selftest` 可以无人值守验证整条链路（自动发两条聊天、让角色绕圈、打印状态包计数与遥测）：

```powershell
.\run_game.ps1 -NetHost -NetName 主机甲   # 再加 -NetSelftest 见下
```

当前自检参数通过 cmdline 透传，等价命令：

```
--net-host=45911 --net-name=主机甲 --net-selftest
```

## 八、下一步能加什么（按性价比排序）

1. **玩家头顶名字**：`state` 里加一个姓名下标，用 `Label3D` 挂在远端代理上（半小时的事）。
2. **远端角色的说话气泡**：收到聊天时在对应代理头顶飘 3 秒。
3. **服务器权威校验**：现在客户端是「自报位置」，只适合校内试点演示，不适合长期运营。
4. **场景内交互事件**（开关门、占座位）：定义少量 RPC 事件即可，不必做完整状态机。
5. **专用服务器模式**：已经做了，见第二节的 `-Server`。

## 九、单机自测：已验证的路径与实测证据

### 9.1 结论

**一台机器可以测，但只能开一个图形窗口。** 推荐：

| 场景 | 做法 | 图形窗口数 |
|---|---|---|
| 单机看到「另一个玩家在我场景里」 | **`OPEN_NET_DEMO.cmd`**（双击一次） | **1** |
| 两台机器玩真的 | 各自双击 `OPEN_NET_HOST.cmd` / `OPEN_NET_JOIN.cmd` | 各 1 |
| 单机开两个窗口互玩 | 先腾内存到 6 GB+ 可用 | 2（不推荐） |

### 9.2 `OPEN_NET_DEMO.cmd`（本次新增）

双击一次即可：后台起一个**无窗口主机**（带 `--net-selftest`，它的角色会绕郭沫若广场跑圈），
等 15 秒后自动开**一个**客户端窗口。在客户端窗口里你能看到另一个学生在广场上跑——
那就是网络复制过来的远端玩家。全程只有一个图形实例，绕开了双窗口的内存问题。

关闭客户端窗口后，请手动关掉 `ustc-net-server` 那个最小化的控制台窗口。

### 9.3 实测证据（2026-10-13 补测）

用 `run_game.ps1 -Server -NetSelftest` + 一个客户端跑通，两端日志一致：

| 项目 | 结果 |
|---|---|
| 无窗口主机建立会话 | `NET_READY mode=host name=同学 port=45888 peer_id=1` |
| 客户端连接 | `已连接到主机` → `玩家 1 加入` → `玩家 1 进入场景` |
| 远端角色被复制 | `remote_avatars=1`，累计 `states_recv=631` |
| **远端角色确实在动** | 遥测 `gap_m=0.57, yaw=-4.973, grounded=true`（yaw 持续变化 = 在绕圈跑） |
| 脚本错误 | 客户端 **0**，主机 **0** |

> 之前 `runtime.log` 里那次崩溃留下的 `NET_CHAT 鍚屽：你好` 是**旧版启动脚本的编码问题**
> （cmd → 参数按 ANSI 代码页传递，中文名变乱码），现已随脚本改为纯 ASCII 而消失；
> 现在日志里显示的是 `name=同学`。

### 9.4 环境层面的两个额外发现

排查时用 `Get-CimInstance Win32_VideoController` 看到的适配器列表：

```
NVIDIA GeForce RTX 5060 Ti      driver 32.0.16.1062
AMD Radeon(TM) Graphics         driver 32.0.21030.2001   ← CPU 核显
GameViewer Virtual Display Adapter  driver 15.6.5.199    ← 虚拟显示器
```

- **同一台机器上有三个显示适配器**。主的崩溃原因是内存不足（`Couldn't create Vulkan swapchain`
  之后紧跟 `Parameter "mem" is null`，然后 signal 11），但 `SURFACE_LOST_KHR` 这类
  表面错误在「核显 + 独显 + 虚拟显示器」共存时也更容易出现。
- **建议**：确认显示器是接在独显上（不是主板视频口），并且跑之前把 GameViewer /
  远程串流类程序退出，它们会插一层虚拟显示器，可能让窗口表面和 Vulkan 队列对不上。
- 两个图形实例大约要 **6 GB 可用内存** 才稳，所以自测前先关掉浏览器、聊天客户端之类的常驻程序。
